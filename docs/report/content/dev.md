# Welcart Tiered Discounts

## できること

「10,000円以上で500円引き」「30,000円以上で2,000円引き」のように複数段を設定し、条件を満たす最も高いしきい値の1段を適用します。各段では固定額または割合を選べます。

判定対象は登録販売価格×数量の商品小計です。税込運用は税込価格、税抜運用は税抜価格を使い、送料・手数料・別途加算する税・利用ポイントは判定額に含めません。割合割引の円未満は切り捨て、商品代金を割引上限とします。

カート、購入確認、受注データに同じ割引を反映します。受注編集では、注文時の設定を使って数量変更後の割引を再計算し、元注文と変更履歴を保持します。

## 導入方法

1. WordPressにWelcartを導入し、有効化します。
2. GitHubから参考版（dev）を取得し、`plugin/`の中身を`wp-content/plugins/welcart-tiered-discounts/`へ配置します。
3. WordPressのプラグイン画面で「Welcart Tiered Discounts」を有効化します。
4. 「設定 → ステップ割引」で割引条件を保存します。

GitHubの「Download ZIP」はリポジトリ全体のアーカイブです。展開して上記の配置を行ってください。

## 動作確認手順

税込10%・販売価格10,000円の商品を用意します。送料・手数料・利用ポイントを0にし、「10,000円以上500円」「30,000円以上2,000円」の2段を設定します。

| 操作 | 確認する結果 |
|---|---|
| 商品1個をカートに入れる | 割引500円、請求9,500円 |
| 購入確認画面へ進む | カートと同じ割引500円、請求9,500円 |
| ローカル検証用の振込方式で注文を確定し、受注データを開く | 商品10,000円、割引500円、内税863円、請求9,500円 |
| 商品3個で同じ購入手順を行う | 商品30,000円、割引2,000円、請求28,000円 |
| 3個の受注を1個に変更し、再計算してから保存する | 注文時の条件で割引500円、請求9,500円。変更履歴が残る |
| 再計算後に数量を再変更し、そのまま保存を試みる | 再計算を要求し、未確認の金額で保存されない |

## 提出版からの追加調整

想定作業時間を超えた後、翌日に追加調整と検証を行った参考版です。主たる提出対象はmainです。

- 税額計算をWelcartの既存関数へ委ね、計算式の重複を減らしました。
- 受注画面の再計算ボタンは、クリックの捕捉からWelcartの既存フィルタによる接続へ変更しました。
- 受注全体の集計は、未保存の追加明細と税率別割引を維持するため、比較の結果プラグイン側の組立てを残しました。
- mainで確認できなかった下限・最新環境の購入経路とメール本文を追加検証しました。

[変更の採否と根拠](https://github.com/satokupo/welcart-tiered-discounts/blob/334907ec022fd7f3babac1e450b43bb77dabbf1e/docs/SSoT/decisions/2026/09/2026-09-08_受注編集は税計算と再計算入口だけnativeへ委ねる.md)

## 未対応・未検証の範囲

- 会員ランク・商品カテゴリの除外条件は未実装です。後続では条件設定と適用判定を追加する想定です。
- i18nは翻訳可能な文言まで対応し、翻訳ファイルの提供は後続としています。
- 他の割引プラグイン・標準キャンペーンとの併用、外部決済の実取引、メールの実配送は保証範囲に含めません。
- Welcart 2.12.1以外の互換性は未検証です。税率別割引の同期には対象版の内部状態への依存が残ります。
