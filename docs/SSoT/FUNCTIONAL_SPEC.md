# 機能仕様

本書は [MVP 定義](MVP_SCOPE.md) に含まれる機能の振る舞いを定める。未決の例外・併用・画面詳細は [確認事項](OPEN_QUESTIONS.md) を参照する。

## 用語と金額の基準

管理画面・購入画面・受注画面に表示する本機能の日本語名は「ステップ割引」とする。

- **ティア**: しきい値金額、割引方式、割引値、有効／無効を持つ 1 段の設定。
- **ティア一覧**: 店舗共通の割引設定 1 組。複数ティアを含む。
- **対象小計 S**: MVP では全商品の登録販売価格 × 購入数量の合計。税込運用なら税込登録価格、税抜運用なら税抜登録価格を使い、税抜への換算は行わない。ポイント・キャンペーン・本プラグインを含む一切の減額を適用する前の金額を使う。
- **割引額 D**: 選択したティアから計算し、対象商品代金全体に 1 回適用する金額。

定価・参考価格を判定基準にしない。送料・手数料と、税抜運用で別途加算される消費税は、しきい値の判定にも割合割引の計算にも含めない。税込登録価格に含まれる消費税は分離しない。円未満の端数処理を前提とし、他通貨への一般化は今回の確定仕様に含めない。

## 管理画面

管理者は複数のティアを登録・編集し、各ティアを有効／無効にできる。保存する項目と構造は [データモデル](DATA_MODEL.md) を参照する。表示はしきい値の昇順とし、手動並び順は持たない。

保存時は nonce 検証、入力の検証・サニタイズ、権限チェックを行い、表示時は出力先に応じてエスケープする。画面を非表示にするだけでは保存権限の保護を満たさない。設定画面と保存処理は `manage_options` 権限を持つ管理者に限定する。

| 入力・状態 | 扱い |
|---|---|
| しきい値・固定額 | 1 円以上の整数 |
| 割合 | 0% 超〜100% 以下、小数第 2 位まで |
| 同じしきい値 | 無効なティアを含めて重複保存不可 |
| 未入力・範囲外・負数・不明な方式・桁数超過・構造不正 | 保存全体を拒否し、旧設定を保持してエラーを表示 |
| nonce 不正・権限不足 | 設定を更新しない |
| 初期状態・空一覧 | 割引なし |

保存済み設定の破損を検出した場合は、購入者への案内と管理画面のエラー表示を行い、復旧まで注文確定を停止する。管理者が原因を調査できるよう、理由コード・処理箇所等を既存の WordPress／PHP エラーログへ記録する。顧客情報、認証情報、設定全文はログへ含めない。初期状態・空一覧は破損と扱わない。

画面側だけに依存せずサーバー側で検証する。数値上限は、対象 PHP と Welcart の金額表現で安全に扱える範囲を実装前に確認する。

## ティアの選択と割引計算

1. 有効なティアのうち、`しきい値 ≤ S` のものを選ぶ。
2. その中でしきい値が最大の 1 件だけを適用する。下位ティアとの累積、最大割引額による選択はしない。
3. 固定額方式では、設定した割引値を対象小計から 1 回差し引く。商品 1 個ごとに引かない。
4. 割合方式では、`D = floor(S × 割引率 / 100)` とし、計算した割引額の 1 円未満を切り捨てる。
5. 実際の割引額は対象小計を上限とする。商品代金を負数にしない。
6. 該当する有効ティアがない場合は割引しない。下位ティアだけが有効で条件を満たす場合は、その下位ティアを使う。

しきい値ちょうどで適用する。割引を適用した後の小計で再判定してティアを下げない。同じカートを再表示・再計算しても、本プラグインの割引が累積しないことが必要。

## ポイント・税・他の割引

標準ポイント等の減額後の金額へ判定基準を切り替える処理は MVP に含めない。S と D は常に減額前の登録販売価格を基準とし、Welcart の既存合計計算へ D を反映する。標準ポイント利用時の最終請求額の整合は維持する。

標準キャンペーンおよび他の割引プラグインとの併用保証、検出・警告・競合時の停止制御は MVP に含めない。判定・計算の入力へ、それらによる減額を混入させない。

登録販売価格の取得箇所と、標準ポイント・税・請求額への反映順序は Welcart 2.12.1 の既存処理で確認する。ポイント利用後の支払金額と商品代金の意味を混同しない。割引後の税額・ポイント利用可能額・最終請求額が連携することを検証し、未確認の順序を数式へ書き足さない（[Q4](OPEN_QUESTIONS.md#q4-他の割引ポイント税計算)）。

## 注文確定と設定変更

注文確定時のティア一覧全体・割引結果・元の注文内容を保存し、後日の店舗設定変更だけで過去の受注金額を再計算しない。購入確認画面の表示後に設定が変わり、適用条件・割引結果・請求額が変わる場合は、確定前に新しい内容を再表示して購入者に確認させる。古い表示のまま新しい金額で注文を確定しない。

管理者が商品・数量を変更した場合は、注文時点のティア一覧全体を使い、変更後の商品・数量から S と D を再計算する。数量減少により下位のティアを選べるよう、適用した 1 段だけを保存する方式は採らない。編集画面に再計算結果を表示し、管理者の保存で確定する。表示・プレビューだけでは受注を更新しない。

元の注文内容と保存済みの変更履歴を追跡できるようにする。各変更の前後の商品・数量・基準価格・適用条件・割引額・請求額、変更日時、操作した管理者を注文に紐付ける。最新の店舗ティアで過去注文を再計算しない。取消・返金の既存処理との接続は実測で具体化する。保存先の判断は [データモデル](DATA_MODEL.md) と [連携資料](INTEGRATIONS.md) に分ける。

## 画面と受注の整合

| 経路 | 必要な結果 |
|---|---|
| カート | 対象カートの割引結果を表示する。数量変更・商品削除で条件から外れた場合に古い割引を残さない。 |
| 購入確認 | 適用した条件、割引額、購入者が確認する金額を整合させる。 |
| 確定後の受注データ | 購入確認に対応した割引結果を保存し、受注側で確認できる。 |
| 決済へ渡す請求額・注文メール・購入履歴等 | 割引の伝播経路と金額・表示への影響を調査する。実際に影響する経路は整合を確認し、未確認を対応済みとしない。 |

最後の行は、全決済サービスへの対応・全画面の改修を無条件に要求するものではない。既存機能で整合する箇所は、その結果を検証する。

追加表示は、割引が適用されたこと、条件、割引結果が理解できる内容にする。具体的な配置・文言は、現行画面を確認し UI 案を可視化した後に確定する（[Q6](OPEN_QUESTIONS.md#q6-画面と連携の実測事項)）。

## 翻訳可能な文言

MVP から、管理画面およびフロントに本プラグインが追加する文言を WordPress の翻訳関数で扱い、一貫した text domain を使用する。Welcart・テーマ全体の翻訳を本プラグインの対象へ広げない。日本語・英語の翻訳提供と切替確認の実施時期は [MVP 定義](MVP_SCOPE.md) に従う。

## 受入例

以下は初期設定値ではなく、判定と計算を検証する入力例。特記しない限り各ティアは有効、他の割引・ポイントは使用しない。

| 条件／操作 | 対象小計 | 期待する割引額・結果 |
|---|---:|---|
| 10,000 円以上で 500 円引き | 9,999 円 | 0 円 |
| 同上 | 10,000 円 | 500 円 |
| 10,000 円以上 500 円、30,000 円以上 2,000 円 | 29,999 円 | 500 円 |
| 同上 | 30,000 円 | 2,000 円。2,500 円にはしない |
| 同上、上位ティアを無効にする | 30,000 円 | 500 円 |
| 10,000 円以上 500 円、30,000 円以上 10% | 30,000 円 | 3,000 円 |
| 1,000 円以上 10% | 1,009 円 | 100 円 |
| 全ティア無効／空一覧／空カート | 任意／0 円 | 0 円 |
| 税抜登録の商品 9,000 円に税・送料・手数料が加算され請求合計が 10,000 円以上、ティアは 10,000 円以上 | 9,000 円 | 0 円 |
| 通常価 12,000 円、登録販売価格 9,000 円、数量 1、ティアは 10,000 円以上 | 9,000 円 | 0 円 |
| 登録販売価格 5,000 円 × 2 個、ティアは 10,000 円以上 500 円引き | 10,000 円 | 合計 500 円引き。1,000 円引きにはしない |
| 30,000 円から数量変更で 9,000 円へ下がる、最小しきい値 10,000 円 | 9,000 円 | 割引解除 |
| 10,000 円・500 円引きのカートを再表示する | 10,000 円 | 毎回 500 円。二重適用しない |

必須 3 箇所の一致、設定保存の保護、他の割引・税・注文確定に関する確認は、単体の計算例とは別に行う。追加の受入条件は次のとおり。ポイント・税額の数値例は対象版の処理を確認した後に具体化する。

| 条件／操作 | 期待する結果 |
|---|---|
| 対象小計 1,000 円に固定額 2,000 円が適用される | 割引額 1,000 円。商品代金は 0 円 |
| 対象小計 10,001 円、10.25% | 割引額 1,025 円 |
| 100% のティア | 対象小計までの割引。商品代金を負数にしない |
| 0 円・負数の金額、0%・100% 超・小数第 3 位の割合、重複しきい値を保存する | エラー。旧設定を保持 |
| 権限なし／nonce 不正で直接保存リクエストを送る | 設定を更新しない |
| 注文確定後に設定を変更する | 過去の受注金額と保存した割引結果は変わらない |
| 購入確認後、確定前に設定が変わり割引結果が変化する | 新しい内容を再確認するまで確定しない |
| 税込登録 10,000 円・数量 1、しきい値 10,000 円・固定額 500 円 | S=10,000 円、D=500 円。送料・手数料・ポイントなしなら請求 9,500 円 |
| 税抜登録 10,000 円・数量 1、同じティア | S=10,000 円、D=500 円。割引後 9,500 円へ Welcart の既存税計算を適用 |
| 登録価格合計 10,000 円からポイント等で 1,000 円減額、しきい値 10,000 円・固定額 500 円 | 判定・計算は減額前の S=10,000 円を使い D=500 円 |
| 保存済み設定の構造が破損 | 注文確定を停止し、購入者・管理者へ案内。内部ログで原因を調査できる |
| 注文時の一覧は 10,000 円以上 500 円・30,000 円以上 2,000 円。受注を 30,000 円から 10,000 円へ編集 | プレビューは当時の下位ティアで 500 円。保存前は既存受注不変、保存後に更新。元注文と前後履歴を保持 |
| 上記受注の後に店舗ティアを変更してから編集する | 最新ティアを使わず注文時の一覧を使う |
| 標準ポイントを利用して注文する | 割引・税・ポイント・請求額が必須 3 箇所で一致し、二重適用や負の請求を生じない |
