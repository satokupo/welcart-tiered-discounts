# docs/SSoT/ 運用ルール（自動ロード）

## このファイルの役割（厳密定義）

このファイルには「AI がこのフォルダ内のファイルを読む・書くときに、毎回認識している必要のあるルール」だけを記載する。索引・読み順・更新手順は持たない（正本は `README.md`）。このディレクトリの `CLAUDE.md` は Claude Code 向けのアダプタであり、`@AGENTS.md` により本ファイルを読み込む。

## 毎回認識ルール

1. **着手前に README**: SSoT 配下を扱う作業（仕様確認・設計・実装・相談）の前に `README.md` の文書マップで読む文書を判定する
2. **SSoT が正**: 会話の記憶・過去の要約と食い違ったら SSoT 側を信じる。ユーザーの発言と食い違ったら、独断でどちらかに寄せず食い違いを明示して確認する
3. **未記入を推測で埋めない**: 「状態: 未着手」の文書・空欄・未掲載は「不要／禁止」ではなく「未決・未整備」を意味する。各文書冒頭の「AI への指示」に従ってユーザーへ聴取し、その回答を本文として書く。**聴取せずに書いた内容は正本にならない**。ユーザーが答えられない項目は `（未決）` と明記して残し、勝手に決めない
4. **正本は1箇所**: 同じ情報を複数の文書に書かない。既に別の文書にあるなら複製せずそこを参照する（出典付きの意図的複製のみ許可し、正本変更時は複製側も同じ作業内で同期する）
5. **構造変更→索引連動**: SSoT 文書の追加・削除・改名・役割変更をしたとき、および文書を書き終えたときは、README の文書マップ・連動更新表を同じ作業内で直す
6. **変更記録**: 仕様・設計の非自明な判断は `decisions/YYYY/MM/` に個別ファイルを作成し、`DECISIONS.md` 索引にも1行足す（書式は `DECISIONS.md` 冒頭の書式ルールに従う）。**片方だけで終わらせない**
7. **書込ゲート**: 判断ログへの記録（`decisions/` への個別ファイル作成と `DECISIONS.md` 索引への追記）は、リポジトリ編集が許可されたセッションのみ。成立事由は次の3つのいずれか——**①このセッションでユーザーから明示的な実装・修正依頼を受けている ②このセッション内で既にユーザー依頼により対象リポジトリのファイルを編集している（過去セッションの編集歴は数えない） ③ユーザーが「DECISIONS に記録して」と記録自体を明示依頼した（その記録に限り成立）**。単なる「覚えて」「記憶して」は成立事由にしない。調査・ブレスト・レビューのみのセッションは不成立。**迷ったら不成立**とし、legacy memoryへ退避せず、応答本文に「SSoT 記録待ち: <決定内容>」を明記して引き継ぐ。**セッションにさらに強い書込制約（レスポンスファイル以外への書き込み禁止等）が課されている場合は、その制約を常に最優先する**
