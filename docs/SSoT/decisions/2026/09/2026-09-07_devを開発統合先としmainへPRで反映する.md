# 2026-09-07: devを開発統合先としmainへPRで反映する

## 決定

ユーザーの指示により、プライマリ worktree のブランチと通常の開発統合先を dev とし、作業ブランチは dev から分岐する。統合・受入確認後に dev から main への PR で安定版へ反映する。

`2026-09-07_開発環境を再利用しDB更新をコードで統合する` の、開発途中の統合先を main とする部分を上書きする。A〜E の分離・再利用と、DB 更新をコードとして各環境へ適用する方針は維持する。

## 理由

プライマリと既存の dev 優先のマージ先判定を揃え、並列作業の統合検証と提出可能な安定版を分離するため。移行時には、既に main に入った変更を dev へ取り込み、変更を失わずに運用を切り替える。
