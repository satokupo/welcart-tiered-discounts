# 2026-09-07: native 注文処理と補助メタを同一 transaction で保存する

## 決定

Welcart 2.12.1 の既存割引 filter と税率別割引プロパティを同期し、既存の請求・税・ポイント計算と受注列を使う。注文時の全設定と元注文は既存 order meta の immutable snapshot、保存した編集の前後値は別メタの追記履歴へ保存する。native 書込みと補助メタを同一 DB transaction で囲み、読み戻しで検証する。管理編集は受注行のロックと fingerprint・署名付きプレビューで競合と未確認入力を拒否する。

## 理由

表示だけの値引きや最終合計だけの上書きは税・ポイント・保存列を置き去りにする。単価変更は登録価格の意味を変え、独自受注テーブルは請求の正本を二重化する。native 管理更新は複数 SQL の失敗を集約せず、取消では金額保存前に戻るため、返却値だけで成功を決められない。実コードの保存順序と故障試験に基づき、既存 API を使った更新を同一接続で囲み、失敗時に DB と session を復元する。外部プラグインの外部副作用まで rollback 可能とはしない。

合意済みの業務仕様は変更しない。採用箇所は INTEGRATIONS.md、データ構造は DATA_MODEL.md、試験の結果と限界は実装・検証レポートを参照する。
